Use Case, Notion + AI Agents

From a spoken note on site to a tracked, closed action in Notion

A system built for a real estate property management operation, where the people closest to the problem are the least able to open a laptop and type it up.

The problem

Typing is not an option on a job site or during a turnover

A property manager overseeing several sites cannot be everywhere, and the people who are on site, maintenance crews, contractors, turnover staff, are rarely in a position to open a phone and type a clean report. Hands are full, gloves are on, or the moment passes before anyone reaches a keyboard. Whatever does not get written down when it happens gets remembered later, badly, or not at all.

The cost is not one missed note. It is a portfolio with no shared, current record of what is happening at each property, and the same issue resurfacing because nothing tracked it the first time.

Capture

A Shortcut turns speech into a Notion page in one motion

The entry point is a custom iPhone Shortcut, triggered by Back Tap or from the Lock Screen, that opens Wispr Flow and transcribes speech on the spot. The Shortcut then hands that transcript to a Notion automation, which creates one page in a single inbox database, stamped with the property, the time and who reported it.

There is no separate app to learn beyond talking, no switching screens, and no keyboard involved at any point. The bar for reporting a problem drops to the same effort as leaving a voicemail.

Triage

AI reads the transcript before any person has to

A spoken note is noisy: no punctuation, false starts, a property named halfway through the sentence. An automation passes each new inbox item to Notion AI and ChatGPT, which extract what happened, the property and unit involved, the urgency, and the action required, then write those back as structured properties on the same page. The item moves from "Note" to "Action" only once that structure exists.

Execution

A router hands the action to sub-agents; a reviewer checks the result

Once an item is marked "Action," a router agent assigns it to the specialist sub-agent built for that kind of work: maintenance dispatch, vendor follow-up, tenant communication. Several of these run in parallel across different open actions, so a maintenance dispatch and a tenant reply are not waiting on each other.

A separate quality reviewer agent checks every output against the original note before the status can move to "Done." Anything the reviewer is not confident about goes to a person for a quick approve or reject rather than closing on its own. The loop is built to catch a mistaken action, not to remove the person from the decision.

Result

One owned record per property, not a scattered text thread

Every voice note ends up as a visible, timestamped, owned item inside the same Notion workspace the rest of the portfolio already runs on. Nothing depends on a text message surviving in someone's phone, or a manager remembering to chase a status update.

Who this changes work for

The person overseeing operations

Visibility into every property from one view, without asking anyone for an update. A record of who reported what, and when. Work distributed to the right agent instead of landing in one shared inbox for someone to sort by hand.

The person on site

A problem gets reported the moment it is noticed, hands stay free, and there is nothing new to learn beyond talking into a phone. Confirmation that the note went somewhere, instead of wondering if anyone will see it.
