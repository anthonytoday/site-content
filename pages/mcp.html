MCP servers I run my business on

The Model Context Protocol (MCP) is how Claude and other AI assistants call real tools. These are the servers and Cloudflare Workers I built so Claude can manage my shop, track template downloads and capture leads without me opening a dashboard. Every one of them is public on GitHub under the MIT license, with the top five use cases and the safety rules built into the code.

How they are used

From a conversation

Each MCP server is added to Claude as a custom connector: one URL and one bearer token. From then on, "unpublish everything tagged exam-prep" or "what did the shop earn in August" is a sentence, not a session in a dashboard.

Secrets stay on the edge

API tokens live as Cloudflare Worker secrets. They are never in the repository, never in the browser, and never in the chat. An unset token fails closed: no access, rather than open access.

Built to be audited

Destructive actions require an explicit confirm. Bulk runs return one result row per record, so a partial failure is visible instead of silent. The same discipline I apply in cybersecurity and GRC work, applied to automation.

Deploy your own

Three commands

Clone the repository, set two secrets with wrangler secret put, run wrangler deploy. Each folder's README carries the exact steps and the Claude connector settings. No framework, no build step, free on Cloudflare's plan at this volume.
